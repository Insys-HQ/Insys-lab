- 연도 기준: **2026년** (문서·코드·주석 모두 2026 기준, 연도 혼동 금지)
- 작성자 이메일: ys.kim@in-sys.co.kr
- 파일명: 짧고 간단한 영문 (예: report.html, guide.docx, pay.html)
- 모든 산출물에 **버전번호 필수** (v1.0 시작 → 수정 시 v1.1 / 대개편 시 v2.0)
- 수정 시: 코드 내 버전값과 화면 표시 버전을 **동시에** 업데이트
- 수정 시: **지시받은 내용만** 수정. 정상 동작 중인 기존 코드 임의 변경 금지
- 전달 전: 오류 여부 **자체 검증 후** 전달 (검증 절차는 §5)

## 2. HTML 규칙

- 폰트: **Noto Sans KR 단일** — Google Fonts `family=Noto+Sans+KR:wght@300;400;500;700;900`
- 최소 폰트 크기: 10px 이상
- 컨테이너: 본문 최대폭 1100px, 커버/헤더는 본문 컨테이너와 동일 너비·중앙 정렬
- nav/header: 배경은 전체 너비, 내부 콘텐츠는 `.nav-inner`로 감싸 본문 max-width·좌우 padding과 일치
- 화면 선택: **모바일/PC 전환 탭(토글) 포함**, 초기값은 모바일
- 여백 최소화: section/card/container의 padding-top/bottom ≤ 12px, margin-top/bottom ≤ 8px
- 캐시 방지 메타태그 필수:
  ```html
  <meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
  <meta http-equiv="Pragma" content="no-cache">
  <meta http-equiv="Expires" content="0">
  ```
- 버전번호를 화면에 항상 표시 (예: 푸터 우측 `v1.3`)
- 데이터 저장: **Firebase** 사용 (§6)
- 색상: 비즈니스 톤. 연한 배경→진한 글자 / 진한 배경→밝은 글자 (저대비 금지)

## 3. 버전 관리 규칙

- 버전 위치 2곳 동시 갱신: ① 코드 내 상수/주석 ② 화면 표시
- 버전 규칙: 버그 수정·소규모 = +0.1 / 구조 변경·대규모 = +1.0
- 커밋 메시지: `파일명 vX.X — 변경 요약` 형식

## 4. GitHub 배포 절차

- 저장소: `Insys-HQ/Insys-lab` (신규 작업용 / 기존 `Insys-review`는 유지)
- 배포 URL 형식: `https://insys-hq.github.io/Insys-lab/파일명.html`
- 업로드 전 반드시 §5 검증 통과
- 업로드는 사용자에게 **업로드 여부 질의 후 Yes 선택 시** 진행
- 업로드 후: GitHub Pages 링크를 응답에 표시 (복사 버튼 포함)
- 수정 후 링크를 열면 **항상 최종 버전**이 보여야 함 (캐시 메타태그 + 버전 확인)

## 5. 검증 절차 (전달 전 필수)

1. 문법 검증: `node --check` (JS) 또는 HTML 파서(jsdom 등)로 구조 오류 확인
2. 규칙 검증: 캐시 메타태그 존재, 버전 표시 존재, Noto Sans KR 로드, 모바일 초기화면 여부
3. 기능 검증: 핵심 동작(데이터 로드, 버튼, 탭 전환) 논리 확인
4. 회귀 검증: 지시받지 않은 기존 코드가 변경되지 않았는지 diff 확인
- **작성 세션과 검증 세션은 분리**한다 (작성자가 자기 결과를 채점하지 않음)

## 6. Firebase 규칙

- 모든 앱 데이터는 Firebase에 저장
- 데이터 스키마 변경 시: 기존 문서와의 호환성 확인 후 반영
- 데이터 정합성 점검 시 판정 기준을 명시 (예: "문서 N개 모두 유효 스키마")

## 7. 문서(docx/PDF) 규칙

- 여백(DXA): 위 1304 / 아래 1020 / 왼 1247 / 오른 907
- 본문폭(TW) = 9752 DXA — 표 컬럼 너비 합계와 반드시 일치
- 폰트: 맑은 고딕 전체, 최소 10pt (size=20)
- 줄간격: before=0, after=0, spacer 단락 최소화
- 표 셀 여백: top/bottom=40, left/right=80
- 표 헤더: 파스텔·밝은 배경 + 진한 글자 (짙은 배경 금지)
- 컬럼 너비: 가장 긴 텍스트 기준 확정 후 나머지 배분
- 페이지 수 최소화 우선

## 8. 조직 컨텍스트

- 경영지원실 = 계열사 전체 세무·회계·인사·총무
- 전략기획실 = 아웃소싱 인력관리·인재서칭·업체관리

## 9. 작업 종료 조건 템플릿 (루프/에이전트 작업용)

작업을 시작하기 전 아래 3항목을 먼저 정의한다.

- **성공 조건**: 기계가 판정 가능한 문장으로 (예: "Firebase 문서 30개 모두 카드로 렌더링")
- **실패 출구**: (예: "5회 시도에도 진전 없으면 사람에게 이관")
- **예산 상한**: 반복 횟수·도구 호출 횟수 한도

'좋아 보이면 완료' 같은 주관 조건 금지.
