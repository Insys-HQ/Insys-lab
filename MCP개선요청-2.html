ERP MCP 개선요청-2 — 현장·라인·배치·근무지 쓰기 도구

버전 v1.1작성일 2026-11-27 인시스 AI혁신 연구개발실ys.kim@in-sys.co.kr
관련: 「ERP MCP 개선요청 — 역할·담당자 배정 도구 (R10) v1.0」(개선요청-1)에 이어지는 건 · 개인정보: 직원 이름 미기재
결론: 2026-11-26~27 「셰플러 창원3공장 현장 분리·GPS 출퇴근 확대」 건의 쓰기 작업은 ERP MCP가 아니라 브라우저 화면 조작(Claude in Chrome) 으로 처리됐습니다. 해결 방법은 현장관리 표에 직접 쓰기 권한을 주는 것이 아니라, 전용 도구(propose → confirm)를 추가하는 것입니다. 함께 ERP 본체의 「현장 소속 회사 자동 지정」 문제도 수정해야 합니다.

1. 발생 건 (2026-11-26~27)

항목 내용
요청 셰플러 창원3공장을 1공장(SITE-064, (주)파인 창원본사)에서 분리해 별도 현장으로 만들고, 근로자 21명을 옮긴 뒤 GPS 출퇴근 적용
실행 권한 요청자(테넌트 관리자)의 Chrome 로그인 세션
실행 클라이언트 Claude (ERP MCP 연결 + Claude in Chrome)

작업별 처리 수단과 결과

작업 처리 수단 결과
현장·직원·배치 조회, 시범 운영 실적 집계 ERP MCP (query_table, aggregate_table, get_field_attendance_settings) 정상
매뉴얼·화면 위치 찾기 ERP MCP (search_manual, find_erp_screen, get_manual_page) 정상
SITE-082 휴지통 이동 브라우저 화면 클릭 완료
SITE-083 신규 등록 (주소, 현장관리자, 맡는 사업장, 라인 4개) 브라우저 화면 입력 완료. 소속 회사가 (주)인시스로 자동 지정됨
SITE-083 소속 회사 수정 브라우저 표 인라인 수정 실패. 「회사」 칸이 보이지만 저장되지 않음
근로자 21명 배치 이동 (SITE-064 → SITE-083) 브라우저 (배치 현황판, 「다른 라인으로 옮기기」, 현장 선택 창) 실패. 회사가 다른 현장은 선택 목록에 나오지 않음
현장 목록 「회사」 열 표시 브라우저 (요청자 개인 보기 설정) 변경됨
전 계열사 인력명단(600명) 일괄 추출 브라우저 JavaScript로 로그인 토큰을 읽어 ERP API 직접 호출 보안 정책에 막혀 실패 (정상 동작). 이 방식은 앞으로 쓰지 않음

브라우저로 처리된 이유

  1. 쓰기 도구 없음: MCP 쓰기는 propose_* 8종(메일, 일정, 할일, 위키, 지출결의서 초안, 카드 계정, 세금계산서 분류, 입금 맞추기)뿐입니다. 현장·라인·배치·근무지 도구가 없습니다.
  2. 조회 칸 부족: list_tables('staffing_site')의 거를 수 있는 칸에 소속 회사(company) 칸이 없습니다. 그래서 회사가 잘못 지정된 현장을 MCP로 찾거나 검증할 수 없었습니다.
  3. 대량 조회 도구 없음: 600명 명단을 만들려면 query_table을 20건씩 약 60번 불러야 해서 브라우저 경로를 시도했습니다.
  4. Claude가 도구가 없다는 사실을 먼저 알리지 않고 브라우저로 진행했습니다. 이 부분은 인시스 지침으로 보완합니다(5장).

브라우저 처리의 문제점

문제 영향
MCP 감사 로그(요청문·도구·입력·결과)에 남지 않음 화면에서는 요청자 본인이 직접 수정한 것으로만 기록되어 AI 작업을 구분할 수 없음
서버 쪽 미리보기·확인 단계 없음 좌표 클릭 오류가 나면 다른 현장·직원에 잘못 반영될 수 있음
하루 실행 횟수 제한 미적용 대량 배치 이동을 통제할 수 없음
요청자 PC의 Chrome 세션 필요 다른 직원, 모바일, ChatGPT에서는 같은 처리를 할 수 없음

2. ERP 본체 결함 (MCP와 별개, 우선 수정)

No 결함 재현 요청
B1 현장 등록 시 소속 회사가 등록자의 회사로 자동 지정됨 관리자(소속 (주)인시스) 계정으로 왼쪽 위 회사를 (주)파인 창원본사로 바꾼 뒤 현장을 등록해도, 소속 회사가 (주)인시스로 저장됨 (SITE-082, SITE-083 두 번 재현) 등록·수정 화면에 「소속 회사」 칸을 열기. 최소한 테넌트 관리자는 수정할 수 있게 하기. 기본값은 화면에서 고른 회사로 하기
B2 현장 목록 표 수정 기능의 「회사」 칸이 입력되는 것처럼 보이지만 저장되지 않음 현장 목록 ▸ 표 수정 ▸ 회사 칸 변경 ▸ 저장 → 값이 그대로 저장되지 않는 칸은 읽기 전용으로 표시
B3 회사가 다른 현장으로 배치를 옮길 때 안내가 없음 배치 상세 ▸ 현장 선택 창에 다른 회사 현장이 보이지 않음 「소속 회사가 달라 이동할 수 없음」 안내 표시

긴급 데이터 수정 요청: SITE-083 「셰플러 창원3공장(파인)」의 소속 회사를 (주)파인 창원본사로 바꿔 주세요(DB 또는 Studio). 수정되면 21명 배치 이동과 GPS 출퇴근 설정을 진행합니다.

3. 결론: 「테이블 쓰기 권한」이 아니라 「전용 도구 추가」

방안 판단 이유
A. staffing_site·staffing_placement 표에 AI 직접 쓰기 권한 부여 비추천 화면 저장 시 하는 후처리(근무지 자동 생성, 담당자 자동 지정, 배치 기간 분할, 변경 이력)를 건너뛸 수 있음
B. 전용 도구 추가 (propose → confirm) 추천 기존 MCP 쓰기와 같은 방식. 미리보기·확인·횟수 제한·감사 로그가 자동으로 적용됨
C. 조회 칸 보강 (company 칸 노출, 대량 내보내기) B와 함께 처리 전후 검증과 데이터 점검에 필요

4. 요청 도구 정의

우선 도구명 대상 기능 주요 입력 미리보기·출력 쓰기
★1 propose_site_upsert 현장(staffing_site) 현장 등록·수정 현장 ID(수정 시), 소속 회사, 고객사, 현장명, 주소, 현장관리자, 맡는 사업장, 현장유형 변경 전·후 값, 경고, action_id 예(제안)
★1 propose_line_upsert / propose_line_delete 라인·구역 라인 등록·이름 변경·삭제 현장 ID, 라인명 목록 라인 목록 변경 전·후, 배치 인원이 있는 라인 삭제 경고 예(제안)
★1 propose_placement_move 배치(staffing_placement) 여러 명 배치 이동 직원 목록, 대상 현장·라인, 적용일(기본: 기존 배치 시작일 유지) 직원별 전·후 현장·라인, 기간 분할 여부, 회사 불일치 경고 예(제안)
★2 propose_field_attendance_setup 현장 출퇴근 근무지·정책 출퇴근 켜기, 반경, 근무·휴게 시각, 담당자 권한 현장 ID, 반경(m), 근무 시각, 담당자 설정 전·후 값 예(제안)
★2 propose_record_trash / propose_record_restore 현장·라인 공통 휴지통 이동·복구 (영구 삭제 제외) 표 이름, 레코드 ID 연결된 배치·근무지 수 예(제안)
★3 export_table hr_employee, staffing_placement 등 권한 범위 안에서 전체 목록 내려받기 (CSV/XLSX) 표 이름, 칸 목록, 필터 파일 링크, 행 수. 민감 칸은 칸 목록에 넣은 경우만 아니오
★3 propose_send_attendance_link 현장 근로자 개인 출퇴근 링크 문자 발송 현장 ID, 직원 목록 발송 대상 수, 문자 미리보기 예(제안)
- confirm_proposal (기존) 공통 제안 실행 action_id 화면 저장과 같은 후처리로 반영 예(확정)

조회 보강

  1. list_tables / query_table: staffing_site에 company_id(소속 회사) 칸 노출. staffing_line, 현장 출퇴근 근무지 표도 조회 대상에 넣기
  2. 휴지통 레코드 조회 옵션 (include_trashed)

미리보기에 꼭 넣을 경고

  1. 현장 소속 회사 ≠ 근로자 소속 회사 (이번 건 사례)
  2. 같은 고객사·주소에 이미 현장이 있음 (중복 등록 의심)
  3. 삭제하려는 라인·현장에 배치 인원이나 근태 기록이 있음
  4. 배치 이동으로 기존 배치 기간이 나뉨, 또는 월 근태 확정 기간과 겹침
  5. 변경 인원이 많음 (예: 30명 이상)

5. 권한·안전 규칙

  1. 권한 상속: 연결한 직원의 ERP 역할 권한을 그대로 따릅니다. 현장관리 권한이 없으면 forbidden
  2. 1차 공개 범위: 현장, 라인, 배치, 현장 출퇴근 근무지·정책만. 급여, 4대보험, 주민번호 등 민감 칸은 제외
  3. 영구 삭제는 제공하지 않음. 휴지통 이동·복구만
  4. 하루 AI 실행 횟수 상한 (예: 제안 20건, 배치 이동 1회 50명 이하)
  5. 감사 로그: 사용자, 시각, 클라이언트(Claude / ChatGPT / ERP 비서), user_request, 변경 전·후 값, 승인자
  6. 화면 처리와 같은 알림·후처리 적용 (근무지 자동 생성, 담당자 자동 지정 등)

인시스 측 지침 보완 (Claude 공통 지침에 추가)

- ERP 쓰기 요청은 ERP 도구(propose_* → confirm_proposal)로 먼저 처리한다.
- 맞는 ERP 도구가 없으면 브라우저로 바로 진행하지 말고
  "ERP 도구에 이 기능이 없음 → 브라우저 화면 조작으로 처리 가능"을 먼저 알리고 확인을 받는다.
- 브라우저의 로그인 토큰을 읽어 ERP API를 직접 호출하지 않는다.
- 브라우저로 처리한 쓰기는 경로·변경 전후·시각을 답변에 남긴다.

6. 개발사 전달용 이슈

[ERP-이슈] MCP에 현장·라인·배치·근무지 쓰기 도구 없음 + 현장 소속 회사 자동 지정 결함
- 발생일시 : 2026-11-26 ~ 11-27
- 클라이언트 : Claude (ERP MCP 연결 + 브라우저)
- 모듈·메뉴 / 경로 : 현장관리 › 현장 (/table/staffing_site), 배치, 현장 출퇴근 설정
- 사용자 맥락 : 테넌트 관리자, 소속 (주)인시스
- 재현 절차 : 1) 왼쪽 위 회사를 (주)파인 창원본사로 선택
              2) 현장 신규 등록 → 저장 → 소속 회사가 (주)인시스로 저장됨
              3) 표 수정에서 회사 칸 변경 → 저장되지 않음
              4) 배치 이동 시 해당 현장이 선택 목록에 나오지 않음
              5) MCP에는 현장·배치 쓰기 도구가 없고, staffing_site 조회에 company 칸이 없음
- 기대 결과 : 소속 회사 지정·수정 가능
              propose_site_upsert / propose_placement_move 미리보기 → confirm_proposal 실행, 감사 로그 기록
- 실제 결과 : 화면에서 회사 수정 불가, MCP로 조회·변경 모두 불가
- 영향 범위 : 계열사별 현장 신설·분리, 배치 이동, GPS 출퇴근 확대 전체
- 우선순위 : 높음 (B1 결함 + SITE-083 데이터 수정은 GPS 출퇴근 확대 일정에 직접 영향)
