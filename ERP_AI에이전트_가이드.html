ERP AI 에이전트 도입 가이드 v1.1 인시스 AI혁신 연구개발실 · 2026-11-24

직원이 ERP를 배우는 대신, AI가 ERP를 대신 다룬다

직원은 말·사진·엑셀로 요청만 → AI 에이전트가 계열사·양식에 맞춰 임시저장 → 직원 확인 → 등록. 오류는 개발 AI에게 자동 리포트.

오류가 나면: "결재선 미지정 오류로 개발팀에 리포트 #142 접수했습니다. 처리되면 알려드릴게요."

현재 문제 진단

증상근본 원인
챗봇이 엉뚱한 답낮은 성능 모델 + ERP 기능 지식 없음 + 현재 화면·권한 정보 없음
영상·퀘스트 볼 시간 없음교육이 업무와 분리 → 이중 업무

개선 요청이 느림말로 전달, 재현 정보 부족

에이전트 3종

역할하는 일
① 안내영상 자막·위키·공지 기반 답변, 필요 시 영상 해당 구간 제시
② 입력 대행증빙에서 계열사 판별 → 양식 작성 → 직원 확인 → 임시저장
③ 오류 리포트실패·이상 감지 시 개발 AI용 이슈 자동 작성

에이전트는 임시저장까지만. 결재 상신·승인·삭제는 사람이 버튼으로 수행. 권한은 요청한 직원의 권한을 그대로 따름.

비즈니스 계정 ≠ API

구분용도과금ERP 연결
Claude Team·Enterprise / ChatGPT Business직원이 웹 화면에서 직접 사용1인당 월정액불가
API (Bedrock, Claude API, OpenAI API)우리 시스템에 AI 내장사용량필요

Anthropic은 기업용(API) 입력·출력을 기본적으로 모델 학습에 쓰지 않음. OpenAI는 계약 전 별도 확인.

AWS에서 Claude 쓰는 3가지 경로

경로특징적합도
① Amazon BedrockAWS 운영, 서울 리전 안에서만 처리 가능, AWS 요금 합산1순위
② Claude Platform on AWSAnthropic 운영·AWS 결제, 최신 기능 빠름(Managed Agents)고급 기능 필요 시
③ Claude API 직접별도 계약·API 키 관리시범 테스트

모델 선택(Bedrock 서울)

  • 개인정보 포함 가능 업무(경비·인사): 서울 리전 내 처리 Claude Sonnet 5
  • 개인정보 없는 업무(사용법 안내): 최신 Claude Sonnet 5.5(글로벌 처리) 또는 Haiku

연결 절차 (AWS 관리자 + 개발자)

  1. AWS Bedrock 콘솔 → 우측 상단 리전을 아시아 태평양(서울)으로 선택
  2. 왼쪽 메뉴 모델 액세스(Model access) → Anthropic Claude 사용 신청
  3. IAM 역할 생성: ERP 서버에 bedrock:InvokeModel 권한만 부여 (API 키 없음 → 유출 위험 없음)
  4. AWS Budgets로 월 예산 알림(초기 50만 원, 80% 도달 시 메일)
  5. 개발자가 ERP 백엔드에 에이전트 서버 모듈 추가
  6. (선택) OpenAI 비교 테스트 시 키는 AWS Secrets Manager에만 저장

필수 안전장치

  1. 임시저장까지만, 결재·삭제·금액 확정은 사람
  2. 쓰기 전 미리보기 + 사용자 확인
  3. 감사로그(누가·언제·요청·도구·결과)
  4. 급여·평가·주민번호 조회 제외 또는 마스킹
  5. 업로드 문서·이미지 속 "지시문"은 실행하지 않음
  6. 1회 처리 건수·금액 한도

지식 자동화

  • 영상 90개 → 자막 추출 → 메뉴별 가이드 문서
  • 공지(업데이트) 등록 시 지식 자동 반영
  • 답 못한 질문 주간 리포트 → 가이드 보강

자동 작성 조건

  • 도구 호출 실패(서버·필수값·권한 오류)
  • 결재선 미지정·이상 결재선 감지
  • 직원이 👎 또는 "이거 안 돼요"라고 말한 경우

리포트 양식 (개발 AI가 바로 읽는 형식)

[ERP-이슈] 법인카드 경비 임시저장 시 결재선 미지정
- 발생일시/ID : 2026-11-24 10:32 / #142
- 모듈·메뉴  : 경비관리 > 법인카드 > 사용내역 등록
- 사용자 맥락 : 직무=회계담당, 담당법인=(주)A,(주)B
- 재현 절차  : 1) … 2) … 3) …
- 기대 결과  : 담당 → 실장 → 대표 결재선 자동 지정
- 실제 결과  : 결재선 공란, 기본 관리자로 상신
- 오류 로그  : (API 응답 원문)
- 영향 범위  : 동일 조건 직원 n명 추정
- 제안 방향  : 직무 템플릿 기반 결재선 조회 로직 점검
- 우선순위   : 높음 / 중간 / 낮음

처리 흐름

  1. 에이전트 리포트 → 관리자 검토함(중복·개인정보 확인)
  2. 관리자 승인 → GitHub Issue 등 개발 AI 작업 큐
  3. 개발 AI 수정 → 개발자 검토 → 배포
  4. 업데이트 공지 자동 작성 → 지식 갱신 → 직원에게 "해결됨" 알림

에이전트는 권한·결재선 데이터를 그대로 따르므로, 이 데이터가 정리돼야 에이전트도 정확합니다.

3개 축 분리

축의미관리
법적 소속급여·4대보험 기준 법인인사 마스터
업무 담당실제 처리하는 법인들담당자 매트릭스
직무(역할)회계·인사·총무·채용 등직무 템플릿

원칙

  1. 경영지원실·전략기획실은 조직도상 공유서비스 조직 1개로 표시
  2. 권한은 사람별이 아니라 직무 템플릿으로 부여
  3. 결재선은 직무 × 법인 규칙, 표준 3단계: 담당 → 실장 → 대표
  4. 결재선 미지정 시 임의 관리자로 보내지 않고 "결재선 오류"로 멈춤 + 관리자 알림
  5. 담당자 매트릭스 1장(사람 × 법인 × 직무)을 원본으로 ERP에 일괄 반영
  6. 에이전트가 매주 매트릭스와 ERP 설정 불일치 점검

대표이사

  • 비전: "말하면 ERP에 들어가는 회사"
  • 결정: API 예산 승인, 퀘스트 선택 전환, 결재선 표준 3단계

직원

  • 메뉴를 외우지 말고 챗봇에 말하거나 사진 업로드
  • 미리보기는 반드시 확인 후 저장
  • 이상하면 "이거 이상해" → 리포트 자동 접수
  • 영상·퀘스트는 선택

관리자(연구개발실)

  • 담당자 매트릭스·직무 템플릿 관리
  • 주 1회: 이슈 검토, 답 못한 질문 보강, 비용 확인
  • 에이전트 규칙 버전 관리

개발자(개발 AI)

  • 개발 요구사항 구현, 이슈 양식 수용
  • 배포마다 변경 내역을 공지 형식으로 기록
