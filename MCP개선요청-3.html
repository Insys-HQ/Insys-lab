ERP MCP 개선요청-3v1.0

ERP MCP 개선요청-3 — Claude·ChatGPT 부서 간 업무 연계 도구

버전 v1.0작성일 2026-11-27 인시스 AI혁신 연구개발실ys.kim@in-sys.co.kr
관련: 「MCP개선요청-2 — 현장·라인·배치·근무지 쓰기 도구」에 이어지는 건 · 개인정보: 직원 이름 미기재
결론: 부서마다 다른 AI(경영지원실 ChatGPT Business, 다른 부서 Claude)를 쓰더라도 같은 업무를 이어서 처리하려면 AI끼리 직접 연결하지 않고 ERP를 공용 작업장(허브)으로 씁니다. 두 AI는 이미 같은 ERP MCP에 연결돼 있습니다. 다만 부서 간 업무 요청 등록, 댓글, 상태 변경 도구가 없어서 보강이 필요합니다.

1. 배경

항목 내용
현재 사용 경영지원실은 ChatGPT Business, 그 밖의 부서는 Claude로 ERP MCP에 연결 (2026-11 기준)
문제 AI 대화 기록은 각 개인 계정에만 남습니다. 다른 부서 담당자나 다른 AI가 그 업무를 이어받을 수 없습니다
요구 쓰는 AI가 달라도, 한 부서가 요청한 업무를 다른 부서가 받아 처리하고, 결과를 다시 요청한 쪽이 이어서 쓸 수 있어야 합니다

2. 연결 방식 검토

방법 방식 장점 단점 판단
A. ERP를 허브로 두 AI가 같은 ERP의 업무 요청·할 일·댓글·위키를 읽고 씀 이미 연결돼 있음. 기록·권한·감사 로그가 ERP에 남음 지금은 쓰기 도구가 일부뿐이라 보강 필요 추천
B. 공용 문서 저장소 M365(SharePoint·OneDrive)를 두 AI에 각각 연결해 같은 파일을 봄 엑셀·보고서 공유가 쉬움 진행 상태와 담당자를 관리할 수 없음 보조
C. AI끼리 직접 연결 Claude API를 감싼 MCP 서버를 ChatGPT에 연결(또는 반대) 한쪽 AI에서 다른 AI를 호출 가능 API 비용 추가. 권한·로그가 ERP 밖으로 나감. 개인정보가 두 회사 서버를 오감 비추천

연결 구조: 경영지원실(ChatGPT) ⇄ ERP MCP ⇄ ERP(공용 기록) ⇄ ERP MCP ⇄ 다른 부서(Claude)

3. 목표 업무 흐름 (예시)

단계 요청 부서 (ChatGPT) 처리 부서 (Claude) 사용할 도구
① 요청 "SITE-083 근로자 4대보험 가입 확인을 현장관리팀에 요청해줘" propose_work_request → confirm_proposal
② 확인 "나한테 온 요청 보여줘" list_requests_for_me
③ 처리 ERP 조회 후 처리 결과를 댓글로 등록, 상태를 「완료」로 변경 propose_request_comment, propose_request_status
④ 이어받기 "그 요청 처리 결과 알려줘" → 댓글을 읽고 다음 작업 진행 list_requests_by_me, get_request_comments

AI가 바뀌어도 맥락은 ERP 요청 번호 하나로 이어집니다. 대화 기록 대신 ERP 기록이 기준이 됩니다.

4. 요청 도구 정의

우선 도구명 기능 주요 입력 미리보기·출력 쓰기
★1 propose_work_request 다른 부서·담당자에게 업무 요청 등록 받는 부서 또는 담당자, 제목, 내용, 기한, 관련 레코드(현장·직원 등 ID), 첨부 링크 받는 사람, 내용, 기한, action_id 예(제안)
★1 list_requests_for_me 내가(또는 우리 부서가) 받은 요청 조회 상태, 기간, 보낸 부서 요청 번호, 제목, 보낸 사람, 기한, 상태, 화면 링크 아니오
★1 list_requests_by_me 내가 보낸 요청과 처리 상태 조회 상태, 기간 요청 번호, 처리자, 상태, 최근 댓글 아니오
★1 propose_request_comment 요청에 처리 결과·질문 댓글 등록 요청 번호, 내용, 첨부 링크 댓글 미리보기 예(제안)
★2 propose_request_status 요청 상태 변경 (접수 → 처리중 → 완료 / 반려) 요청 번호, 상태, 사유 변경 전·후 상태 예(제안)
★2 propose_request_assign 받은 요청의 담당자 지정·재지정 요청 번호, 담당자 변경 전·후 담당자 예(제안)
★3 첨부 연결 요청·댓글에 ERP 파일 또는 SharePoint/OneDrive 링크 연결 요청 번호, 링크 또는 파일 첨부 목록 예(제안)
- get_request_comments (기존) 요청 댓글 조회 요청 번호 댓글 목록 아니오
- confirm_proposal (기존) 제안 실행 action_id 화면 등록과 같은 알림·후처리로 반영 예(확정)

기존 도구와의 관계 (확인 요청)

  • list_my_requests, list_support_requests, list_my_todos, propose_todo_plan이 이미 있습니다. 이 도구들을 넓혀서 부서 간 요청을 처리할 수 있으면 새 도구 대신 확장해도 됩니다.
  • ERP 화면에 부서 간 업무 요청 기능이 이미 있는지, 있다면 어떤 표·화면인지 알려 주세요.

5. 권한·안전 규칙

  1. 권한 상속: 연결한 직원의 ERP 권한을 그대로 따릅니다. 받는 부서가 볼 수 없는 레코드는 요청 내용에 넣을 수 없게 경고합니다.
  2. 개인정보: 요청·댓글 본문에 주민번호, 계좌번호, 급여 금액이 들어가면 경고하고 막습니다. 원본은 ERP 화면 링크로 연결합니다.
  3. 감사 로그: 사용자, 시각, 클라이언트 구분(Claude / ChatGPT / ERP 비서), user_request, 등록·변경 내용을 기록합니다.
  4. 알림: 화면에서 등록할 때와 똑같이 받는 사람에게 ERP 알림을 보냅니다.
  5. 횟수 상한: 하루 AI 요청 등록 상한을 둡니다(예: 1인 20건).
  6. 삭제 미제공: 요청 삭제는 화면에서만 합니다. AI는 「반려·취소」 상태 변경만 할 수 있습니다.

인시스 측 운영 규칙

- 업무 결과는 AI 대화창이 아니라 ERP 요청·댓글에 남긴다.
- 개인정보는 요약·건수만 댓글로 남기고 원본은 ERP 화면 링크로 연결한다.
- AI는 부서별로 달라도 되지만 회사 계정(ChatGPT Business / Claude Team)만 사용한다.

6. 개발사 전달용 이슈

[ERP-이슈] MCP에 부서 간 업무 요청·댓글·상태 변경 도구 없음 (Claude·ChatGPT 연계)
- 발생일시 : 2026-11-27
- 클라이언트 : Claude, ChatGPT Business (둘 다 ERP MCP 연결)
- 모듈·메뉴 / 경로 : 업무 요청 / 지원 요청 / 할 일 (해당 화면 확인 필요)
- 사용자 맥락 : 경영지원실(ChatGPT)과 기타 부서(Claude)가 같은 업무를 이어서 처리
- 재현 절차 : 1) ChatGPT에서 "현장관리팀에 ○○ 확인 요청 등록해줘" 요청
              2) MCP에 다른 부서·담당자에게 요청을 등록하는 도구가 없음
              3) Claude 쪽에서 받은 요청에 결과 댓글·상태 변경을 할 도구도 없음
- 기대 결과 : propose_work_request → confirm_proposal 로 요청 등록
              받은 쪽은 list_requests_for_me 로 조회, propose_request_comment / propose_request_status 로 처리
              요청 쪽은 list_requests_by_me 로 결과 확인. 모든 단계 감사 로그(클라이언트 구분 포함)
- 실제 결과 : 업무 요청 조회 일부만 가능, 등록·댓글·상태 변경 불가
- 영향 범위 : 부서 간 협업 업무 전체 (경영지원실 ↔ 전략기획실·현장관리·연구개발실 등)
- 우선순위 : 중간 (ERP 본격 도입·전사 AI 계정 전환 일정과 연계)
