# 화재복구·공장신축 TF 통합관리 웹앱 v3.6

담당: 인시스 AI혁신 연구개발실 (ys.kim@in-sys.co.kr)

## 1. 최초 1회, Firebase 콘솔에서 설정할 것

1. **Firestore 데이터베이스 생성**
   콘솔 → Firestore Database → 데이터베이스 만들기 → 프로덕션 모드
   생성 후 "규칙" 탭에 `firestore.rules` 내용을 붙여넣고 게시

2. **Storage 활성화**
   콘솔 → Storage → 시작하기
   생성 후 "규칙" 탭에 `storage.rules` 내용을 붙여넣고 게시

3. **Authentication 활성화**
   콘솔 → Authentication → Sign-in method → "익명" 로그인 사용 설정

4. **로그인 절차 없음 (v1.6부터)**
   Anonymous 인증 방식이 계정 설정에 따라 막혀있는 경우가 있어(관리형 조직 계정 등), 아예 인증 절차를 없앴습니다.
   Firestore/Storage 보안규칙도 "누구나 읽기·쓰기 가능"으로 변경했습니다.
   ⚠️ 이 말은 **접속 주소만 알면 누구나 데이터를 읽고/쓰고/삭제할 수 있다**는 뜻입니다.
   저장소를 비공개로 유지하고 주소를 TF원 외부에 공유하지 않는 방식으로 관리해주세요.
   더 엄격한 접근 통제가 필요해지면 이메일 로그인 방식으로 다시 전환 가능합니다(요청 시 안내).

### 이 저장소를 pull 하신 뒤, Firebase 콘솔에서도 아래 2가지를 반드시 다시 게시해주세요
- Firestore Database → 규칙 탭 → `firestore.rules` 최신 내용 붙여넣고 게시
- Storage → 규칙 탭 → `storage.rules` 최신 내용 붙여넣고 게시

## 4. 법률의견 AI분석 기능 — 설정 방법 (터미널 없이 웹 화면만으로)

"법률의견 AI분석" 탭에서 PDF 업로드 시 Claude(Anthropic API)가 자동으로
핵심쟁점/권고조치/기한/리스크/관련트랙을 분석해 보여줍니다.

### 4-1. Firebase 요금제를 Blaze로 전환
Firebase 콘솔(https://console.firebase.google.com) → insys-work 프로젝트 → 좌측 하단 "업그레이드" → Blaze 선택 → 결제수단 등록
(완료하셨다면 이 단계는 건너뛰세요)

### 4-2. Google Cloud Console에서 함수 생성 (클릭만으로 배포)
1. https://console.cloud.google.com/functions 접속 → 상단에서 프로젝트를 **insys-work**로 선택
2. "함수 만들기" 클릭
3. 기본 설정
   - 환경: **2세대**
   - 함수 이름: `analyzeLegalDoc`
   - 리전: `asia-northeast3 (서울)`
   - 트리거: **HTTPS**, 인증 안 됨(공개 액세스 허용) 체크
4. "런타임, 빌드, 연결 및 보안 설정" 펼치기 → **런타임 환경 변수** 섹션에서 "+ 변수 추가"
   - 이름: `ANTHROPIC_API_KEY`
   - 값: 발급받은 Anthropic API 키(sk-ant-로 시작하는 값) 붙여넣기
5. "다음" 클릭 → 런타임: **Node.js 20**, 진입점: `analyzeLegalDoc`
6. 소스 코드 편집기에서
   - `index.js` 탭에 이 저장소의 `functions/index.js` 내용 전체를 복사해서 붙여넣기
   - `package.json` 탭에 이 저장소의 `functions/package.json` 내용 전체를 복사해서 붙여넣기
7. "배포" 클릭 (2~3분 소요)

### 4-3. 배포된 함수 URL을 앱에 연결
1. 배포 완료 후 함수 상세 화면 상단에 있는 **트리거 URL**을 복사
   (예: `https://analyzelegaldoc-xxxxxxx-du.a.run.app`)
2. `itk-tf/index.html` 파일 안에서 아래 줄을 찾아 복사한 URL로 교체
   ```
   const LEGAL_ANALYZE_URL = "여기에_배포된_함수_URL을_붙여넣으세요";
   ```
3. 수정한 파일을 다시 GitHub에 올리면 (챗봇에게 "다시 올려줘"라고 요청하시면 됩니다) 자동 반영됩니다.

### 확인
https://insys-hq.github.io/Insys-lab/itk-tf/ → 법률의견 AI분석 탭 → PDF 업로드 → 30초~1분 내 분석 결과 표시

### 참고
- 이 방식은 API 키를 Cloud Function의 "환경 변수"로 저장합니다. Secret Manager보다 접근 통제가 느슨하므로,
  이 프로젝트(insys-work)에 접근 권한이 있는 사람만 콘솔에서 값을 볼 수 있다는 점 참고해주세요.
  더 엄격한 보안이 필요하면 이후 Secret Manager로 전환 가능합니다(요청 시 안내).
- 분석 결과는 법적 자문을 대체하지 않는 TF 내부 참고용입니다.
- 현재는 **PDF만 지원**합니다.

## 5. 그 외 다음 단계 (미포함, 확장 검토 필요)

- **카톡 정리**: v1.4부터 이미지 업로드가 아닌 텍스트 붙여넣기 방식입니다. v1.5부터 등록된 내용의 수정도 가능합니다.
- **업데이트 알림**: 새 버전을 배포할 때는 `index.html`의 `APP_VERSION` 값과 `version.json`의 값을 항상 함께 올려야
  접속 중인 사용자 화면에 "새 버전이 배포되었습니다" 안내 배너가 뜹니다. (배포 후 최대 몇 분 내 반영)

- **카톡 캡쳐 AI 자동요약**: 위 법률의견 분석과 동일한 Cloud Functions 구조를 재사용해 확장 가능합니다.
- **접근 권한 세분화**: 현재는 TF원 전원이 같은 암호로 접속·수정 가능한 구조입니다.
  담당자별 로그인/권한 분리가 필요하면 Firebase Authentication을 이메일 로그인 방식으로 전환 필요.

## 6. 공사진행 기능 (v1.9 신규)

공장신축 공정을 **철거 → 기초 → 골조 → 외부마감 → 내부마감 → 준공** 6단계로 관리합니다.

- **공정단계별 진도율**: "공사진행" 탭에서 각 단계별 진행률(%)을 직접 입력·저장
- **날짜별 공사일지**: "사진 타임라인"에서 올린 사진 중 공정단계가 지정된 것만 날짜별로 묶어서 표시,
  상단 드롭다운으로 특정 단계만 필터링 가능
- **일정관리 연동**: 일정 등록 시 "공정단계"를 선택하면 어느 단계의 마일스톤인지 표로 확인 가능

### Firestore 규칙 추가 필요
새 컬렉션 `constructionStages`를 사용하므로, 콘솔의 Firestore 규칙에 아래 블록을 추가로 게시해주세요.
```
match /constructionStages/{doc} {
  allow read, write: if true;
}
```

## 7. 진도율 자동 감지 (v2.2 신규)

카톡 정리에 텍스트를 저장하거나, 사진에 한줄 메모를 남기면 AI가 텍스트를 읽어서
"골조 70% 완료" 같은 명시적 진도율 언급을 자동으로 찾아 화면 하단에 제안 배너로 보여줍니다.
"반영" 버튼을 눌러야 실제 "공사진행" 탭의 진도율에 반영됩니다 (자동 반영 아님 — TF원 확인 필수).

- 막연한 표현("공사 진행중")은 무시하고, 명확한 숫자나 완료 언급이 있을 때만 제안합니다.
- 기존 법률의견 분석 함수(`insys-legal`)를 재사용하므로 추가 배포 비용은 없지만,
  **Cloud Run 콘솔에서 함수 코드를 최신본(`functions/index.js`)으로 다시 붙여넣고 재배포해야 동작합니다.**

## 8. 이미지 자동 압축 (v2.3 신규)

사진 타임라인 / 파일함에 이미지 파일을 업로드하면, 브라우저에서 업로드 전에 자동으로
긴 변 1920px / JPEG 품질 80% 기준으로 리사이즈·압축합니다 (원본 대비 육안 화질 차이는 거의 없음).
압축했는데 오히려 용량이 커지는 경우(이미 작은 이미지 등)는 원본을 그대로 올립니다.
PDF·문서 파일은 압축 대상이 아니며 원본 그대로 업로드됩니다.

## 9. 사진 다중선택 삭제 (v2.4 신규)

사진 타임라인에서 각 사진 좌측 상단 체크박스로 여러 장을 선택한 뒤 "선택삭제" 버튼으로 한 번에 지울 수 있습니다.
"전체선택/해제" 버튼으로 현재 로딩된 사진 전체를 한 번에 선택/해제할 수도 있습니다.

## 10. 진도율 감지 범위 확장 (v2.5)

기존엔 "골조 70%"처럼 명시적 숫자가 있을 때만 진도율을 제안했지만,
이제 "철거 시작"(→5%), "기초 완료"(→100%), "골조 절반 정도"(→50%) 같은
서술형 표현도 자동으로 감지해서 진도율을 제안합니다.
**서버(insys-legal) 함수 코드를 다시 붙여넣고 재배포해야 적용됩니다.** (아래 최신 index.js 참고)

## 11. 촬영일자 관리 (v2.6)

사진 업로드 시 "촬영일자"를 별도로 입력할 수 있습니다 (기본값: 오늘 날짜, 필요시 변경).
화면에는 시:분:초 없이 **년-월-일만** 표시되며, 업로드 후에도 사진 밑 "수정" 링크로 날짜를 바꿀 수 있습니다.
"공사진행" 탭의 날짜별 공사일지도 이제 업로드일이 아닌 **촬영일자 기준**으로 묶입니다.
(기존에 올린 사진은 촬영일자가 없어 업로드일 날짜로 표시되며, "수정"으로 실제 촬영일로 바꿀 수 있습니다.)

## 12. 사진 타임라인 날짜별 그룹핑 (v2.7)

"사진 타임라인" 탭도 이제 촬영일자가 같은 사진끼리 한 날짜 아래 모두 모여서 표시되고,
날짜(YYYY-MM-DD) 내림차순으로 **항상 최신 날짜가 화면 맨 위**에 옵니다. (기존엔 업로드 순서로만 나열됐음)

## 13. 촬영일자 저장 안정성 개선 (v2.8)

촬영일자 수정 후 "저장"을 누르면, 실제로 Firestore에 반영됐는지 즉시 재확인하고
실패 시 화면에 명확한 에러 메시지를 띄우도록 고쳤습니다 (이전엔 실패해도 조용히 넘어갈 수 있었음).

## 14. 일정 수정 + 진도율↔일정 상태 자동연동 (v2.9)

- **일정관리 수정**: 일정 테이블 각 행에 "수정" 버튼 추가 — 트랙/공정단계/내용/일정/상태를 직접 편집 후 저장 가능
- **진도율↔일정 연동**: 카톡/사진 메모에서 감지된 진도율 제안을 "반영" 버튼으로 확정하면,
  "공사진행" 탭의 진도율뿐 아니라 **같은 공정단계·공장신축 트랙의 일정 상태도 자동 갱신**됩니다.
  (진도율 0% → 계획, 1~99% → 진행중, 100% → 완료)
- 예: 사진 메모 "철거 시작" → AI가 철거 5% 제안 → 반영 클릭 → 공사진행 진도율 5% + 해당 "철거" 일정 상태가 자동으로 "진행중"으로 변경

## 15. 사진 메모 수정 (v3.0)

사진 타임라인에서 한줄 메모 옆 "수정" 링크로 메모 내용을 바꿀 수 있습니다.
메모를 수정해서 저장하면 진도율 자동감지도 그 새 내용으로 다시 실행됩니다.

## 16. 사진 표시 위치 통합 (v3.1)

"공사진행" 탭에 사진을 중복으로 보여주던 "날짜별 공사일지" 섹션을 없앴습니다.
사진은 이제 **"사진 타임라인" 탭 한 곳에만** 표시되며, 거기서 공정단계 필터(전체/철거/기초/골조/외부마감/내부마감/준공/기타)로
원하는 단계 사진만 볼 수 있습니다. "공사진행" 탭에는 진도율 카드만 남습니다.

## 17. 헤더 개편 + 트랙현황 → 인허가/현장정보 (v3.2)

- **트랙현황 탭 삭제**: 다른 데이터와 연동되지 않는 단순 메모장이라 혼란을 줘서 제거했습니다.
- **헤더에 날짜·날씨·온습도 표시 추가**: 안산시 기준 실시간 날씨(Open-Meteo, 무료 API·키 불필요)를 헤더 아래 표시합니다.
- **"인허가" 탭 신규**: 건축허가/소방허가/환경인허가/지자체 신축지원 접수 4개 항목 상태 메모
- **"현장정보" 탭 신규**: 주소/대지면적/연면적/층수/시공사/착공일/준공일 입력란. 허가 전이라 현재는 비어있고 추후 입력 예정.

### Firestore 규칙 추가 필요
새 컬렉션 `permits`, `siteInfo`를 사용하므로 콘솔 규칙에 아래 블록을 추가로 게시해주세요.
```
match /permits/{doc} {
  allow read, write: if true;
}
match /siteInfo/{doc} {
  allow read, write: if true;
}
```

### 기존 트랙현황 데이터(trackStatus 컬렉션)
화면에서는 더 이상 안 보이지만 Firestore에는 남아있습니다 (삭제 안 함). 필요시 콘솔에서 직접 삭제 가능합니다.

## 18. 헤더 스타일 개편 + 전체 공사진행률 + 일자별 작업일지 메모 (v3.3)

- **헤더**: 제주 아라이동 주택공사 앱 스타일을 참고해 한 줄 상태바로 개편.
  📍위치 | ☁️날씨·온도 | 💧습도 | 💨풍속(방향) | 🏗️전체 공사진행률(6단계 평균)
  날씨는 안산시 기준(Open-Meteo, 무료 API), 전체 공사진행률은 6개 공정단계 진도율의 평균입니다.
- **일자별 작업일지 메모**: 사진 타임라인의 날짜 그룹 헤더에 그 날짜의 사진 수(🖼️N장)와 작업 요약 메모가
  날짜 옆에 나란히 표시되고, "수정"으로 편집 가능합니다. 이 메모도 진도율 자동감지 대상입니다.

### Firestore 규칙 추가 필요
새 컬렉션 `dailyLogs`를 사용하므로 콘솔 규칙에 아래 블록을 추가로 게시해주세요.
```
match /dailyLogs/{doc} {
  allow read, write: if true;
}
```

## 19. 헤더 디자인 정리 (v3.4)

이모지 아이콘(🏗️📍☁️💧💨 등)이 기기·폰트에 따라 깨져 보이는 문제가 있어서
전부 얇은 선(SVG) 아이콘으로 교체했습니다. 헤더/상태바/일자별 메모 전 구간에 적용했습니다.
구분자도 "|" 문자 대신 얇은 세로선으로 바꿔 좀 더 정돈된 느낌으로 정리했습니다.

## 20. 사진별 메모 제거 (중복 정리, v3.5)

사진 업로드 시 "한줄 메모" 입력란과, 사진 카드마다 있던 메모 표시/수정 기능을 없앴습니다.
메모는 이제 **날짜별(작업일지) 메모 한 곳으로만** 입력·표시·수정합니다 (v3.3에서 추가된 기능).
같은 날짜 사진 여러 장을 올려도 메모는 그 날짜에 한 번만 입력하면 됩니다.

## 21. 제주/전주 앱과 디자인 일체감 (v3.6)

- **버그 수정**: 상태바(위치/날씨/습도/풍속) 컨테이너에 가운데정렬 규칙이 빠져있어 헤더·네비게이션과
  좌우 정렬이 어긋나던 문제를 고쳤습니다 (`.inner` 공통 규칙 추가).
- **헤더에서 "공사진행" 제거**: 위치/날씨/습도/풍속만 남기고, 전체 진행률은 "공사진행" 탭 상단 카드로 이동.
- **상단 통계카드 추가**(제주/전주 앱과 동일한 형태): 사진 타임라인 탭에 "착공 경과일 / 누적 사진 / 기록일수" 3개 카드.
  착공 경과일은 "현장정보" 탭에 착공일을 입력하셔야 계산됩니다 (안 넣으면 "-" 표시).
- **날짜행 스타일 변경**: 날짜를 "8월 31일 (월)" 형태로 표시, 메모는 연필 아이콘이 있는 알약형 박스로 —
  제주/전주 앱과 같은 형태입니다.
